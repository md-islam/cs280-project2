Part 1 · Fun with Filters

1.1: Convolutions from Scratch

Convolution computes a weighted sum of neighboring pixels. I implemented it first with four loops, then with two loops that multiply and sum an entire image patch using NumPy. Both flip the kernel horizontally and vertically.

(I * K)[i,j] = Σ K[u,v] I[i−u,j−v]. The minus signs explain the flip when indexing forward over a patch. Correlation uses an unflipped kernel. A symmetric box filter gives the same result either way, so asymmetric test kernels are needed to catch this error.

My photo and the three filters

I applied EXIF orientation and converted the 1152 × 1536 source photograph to grayscale, then resized it proportionally to 288 × 384. Float intensities lie in [0,1]. The original file is unchanged. The box kernel is np.ones((9, 9)) / 81; the assignment’s difference operators are Dx = [[1, 0, −1]] and Dy = Dx.T. These results use my two-loop convolution.

Original grayscale figure · Box-filter figure

Padding and correctness

Both functions explicitly pad with zeros and return the input shape. Outside the image is treated as black, explaining the dark rim in the box-filter result and artificial derivative responses at the border. For even kernels the extra padded row/column goes on the top/left, matching SciPy’s same-mode alignment. The reference uses convolve2d(image, kernel, mode="same", boundary="fill", fillvalue=0).

The tiny image and kernel are both [[1,2],[3,4]]; the hand-computed answer is [[1,4],[6,20]]. Both functions match it. Each function passed nine cases, including odd, even, rectangular, asymmetric, and larger-than-image kernels, with np.allclose(rtol=1e-12, atol=1e-12). Maximum errors were 7.11 × 10⁻¹⁵ (four loops) and 2.66 × 10⁻¹⁵ (two loops). All three photo filters also matched SciPy; maximum box error was 1.44 × 10⁻¹⁵, and both derivative errors were zero.

Implementation

The convolution functions use NumPy only. SciPy is used separately for comparison.

def convolve_four_loops(image, kernel):
    image = np.asarray(image, dtype=float)
    kernel = np.asarray(kernel, dtype=float)
    height, width = image.shape
    kh, kw = kernel.shape
    padded = np.pad(image, ((kh // 2, (kh - 1) // 2),
                            (kw // 2, (kw - 1) // 2)), mode="constant")
    flipped = kernel[::-1, ::-1]
    result = np.zeros((height, width), dtype=float)
    for row in range(height):
        for col in range(width):
            for u in range(kh):
                for v in range(kw):
                    result[row, col] += padded[row + u, col + v] * flipped[u, v]
    return result


def convolve_two_loops(image, kernel):
    image = np.asarray(image, dtype=float)
    kernel = np.asarray(kernel, dtype=float)
    height, width = image.shape
    kh, kw = kernel.shape
    padded = np.pad(image, ((kh // 2, (kh - 1) // 2),
                            (kw // 2, (kw - 1) // 2)), mode="constant")
    flipped = kernel[::-1, ::-1]
    result = np.zeros((height, width), dtype=float)
    for row in range(height):
        for col in range(width):
            patch = padded[row:row + kh, col:col + kw]
            result[row, col] = np.sum(patch * flipped)
    return result

Key ideas

  • Convolution flips the kernel; correlation does not.
  • Zero padding affects border pixels even when interior values are correct.
  • A box filter averages; difference filters measure directional brightness changes.
  • Derivative signs matter, and display scaling must preserve the underlying data.
  • Numerical correctness and runtime are separate questions.

Implementation notes

  • The padding widths and kernel[::-1, ::-1].
  • The four nested loops versus np.sum(patch * flipped).
  • The tiny hand-computed answer and np.allclose checks.
  • The normalized box filter and the two derivative kernels.
  • The warmup, perf_counter, and median of three measurements.

Boundary-handling lesson

The most important idea from this section is that boundary handling is part of the operation. Matching a kernel alone is not enough to match another implementation’s output. The asymmetric test also catches a missing flip that a symmetric box filter would hide.

Mandatory CS280A

Gradient orientation

The gradient vector points toward the strongest local intensity increase. Its length is edge strength; its direction is perpendicular to the local visible edge tangent, rather than along that edge.

I use smoothed derivatives and angles in [0, 2π). Image coordinates have x right and y down, so angles increase clockwise: 0 right, π/2 down, π left, and 3π/2 up.

The code computes one-argument arctangent only where |dx| > 1e-12, corrects both negative-dx quadrants, and assigns vertical directions explicitly from dy. Gradients of magnitude ≤ 1e-12 have undefined direction; their stored zero is a placeholder and they are masked. No built-in full-angle helper is used.

def manual_orientation(dx, dy, epsilon=1e-12):
    orientation = np.zeros_like(dx, dtype=float)
    nonvertical = np.abs(dx) > epsilon
    orientation[nonvertical] = np.arctan(dy[nonvertical] / dx[nonvertical])
    upper_left = nonvertical & (dx < 0) & (dy >= 0)
    lower_left = nonvertical & (dx < 0) & (dy < 0)
    orientation[upper_left] += np.pi
    orientation[lower_left] -= np.pi
    vertical = ~nonvertical
    orientation[vertical & (dy > epsilon)] = np.pi / 2
    orientation[vertical & (dy < -epsilon)] = -np.pi / 2
    orientation = orientation % (2 * np.pi)
    zero_gradient = np.sqrt(dx**2 + dy**2) <= epsilon
    orientation[zero_gradient] = 0.0
    return orientation

Hue = angle/(2π), saturation = 1, and value = clip(magnitude/0.15, 0, 1). Pixels with magnitude ≤ 0.06 and the outer five pixels are black. Black means masked, not orientation zero. The value cap is only a display scale.

Validation passed 12 explicit axis/quadrant/zero/near-zero cases and 721 directions generated from known sine/cosine values. Maximum circular error was 4.44 × 10⁻¹⁶ radians. Checks also confirm finite values, the stated angle range, and black pixels wherever the mask is false.

Key ideas

  • Dx and Dy form a two-dimensional gradient vector.
  • One-argument arctangent needs explicit quadrant correction.
  • Vertical and zero gradients require special handling.
  • The angle convention follows image coordinates, so positive angles appear clockwise.
  • Orientation is cyclic and normal to the local visible edge.

Implementation notes

manual_orientation, division mask, negative-dx corrections, vertical branches, modulo 2π, known-angle tests, orientation_mask, and HSV hue/value construction.

Part 2 · Fun with Frequencies

2.1: Image Sharpening

Gaussian blur is a low-pass filter: it keeps broad color and intensity structure while reducing rapid changes. Subtracting it from the original leaves a signed residual containing edges and fine texture. Adding a scaled copy back increases local contrast and makes details appear sharper.

blurred = filter_rgb(original, gaussian)
high_freq = original - blurred
sharpened = original + alpha * high_freq

The equivalent single filter is K = (1 + alpha) delta − alpha G, because I + alpha(I − I*G) = I*((1 + alpha)delta − alpha G). Delta is a centered impulse; G is the normalized Gaussian. K sums to one and preserves constant regions. The notebook applies this kernel and compares it against the explicit steps.

For sharpening, I used a 9×9 Gaussian, sigma = 1.5 pixels, constructed with cv2.getGaussianKernel and an outer product. Each RGB channel is filtered independently with symmetric boundary extension. All calculations use float64; only display copies are clipped to [0,1].

Taj Mahal and alpha exploration

The official Taj Mahal image is stored in images/input/taj.jpg and used at its native 300×300 resolution. I tested alpha = 0.5, 1, and 2.

After inspecting these outputs, I prefer alpha = 1. Alpha 0.5 gives a mild contrast increase; alpha 1 makes the decorative patterns clearer. At alpha 2, architectural bands become harsh, bright/dark edging is more noticeable, and pixel-level texture is emphasized. Before clipping for display, 4.77%, 7.55%, and 12.64% of RGB channel values fall outside [0,1] for the three strengths.

Additional image: my existing portrait

I used the existing my images/input/me.jpg, applied EXIF orientation, and resized it proportionally from 1152×1536 to 480×640 before filtering. Parameters: 9×9 Gaussian, sigma 1.5, alpha 1. This uses the same setting as the preferred Taj Mahal result, rather than claiming a separate portrait parameter search.

The glasses, beard, shirt lettering, and wall texture stand out more. Broad skin and wall colors are near neutral gray in the residual; most visible residual structure follows edges and texture. Sharpening also emphasizes background texture that may not be desirable.

Blur, then re-sharpen

The portrait at its 480×640 working resolution is the preserved sharp reference. I deliberately blurred it with a 13×13 Gaussian, sigma 2, then sharpened that blurred image using the 9×9 Gaussian, sigma 1.5, alpha 1. The high-frequency residual for this step is computed from the blurred image, not from the reference.

The re-sharpened image has stronger contrast than the blurred version, but fine detail remains visibly softer than the original. MSE relative to the reference falls from 0.00164242 after blur to 0.00127803 after re-sharpening, measured on unclipped RGB floats. This is an improvement, not a reconstruction: unsharp masking boosts surviving structure and does not invert the original blur.

Key ideas

  • Low frequencies represent broad, slowly varying structure.
  • High frequencies include boundaries, fine texture, and noise.
  • Gaussian averaging attenuates rapid spatial changes.
  • Original minus blur produces a signed high-frequency residual.
  • Alpha controls the residual's contribution and can produce overshoot or halos.
  • Unsharp masking enhances surviving detail; it does not reconstruct detail removed by blur.

Implementation notes

  • gaussian_kernel and filter_rgb: Gaussian construction, separate RGB channels, symmetric boundaries.
  • high_freq = original - blurred: signed float residual.
  • original + alpha * high_freq and (1 + alpha) * impulse - alpha * gaussian: two equivalent formulations.
  • plot_sharpening: centered signed display and clipping only display copies.
  • The evaluation computes its residual from the already blurred image.

A hybrid adds broad structure from one image to fine detail from another. Gaussian low-pass filtering gives the smooth component; subtracting a Gaussian blur from the other source gives its signed high-frequency component. Part 2 · Fun with Frequencies

2.3: Gaussian and Laplacian Stacks

A Gaussian stack stores progressively smoother versions of an image. A Laplacian stack stores differences between neighboring Gaussian levels, plus the final smooth residual. Every level here remains 300×300 RGB: these are stacks, with no downsampling.

The official apple and orange inputs were extracted unchanged from the course archive on the migrated Fall 2024 host. Sources: apple.jpeg and orange.jpeg.

Construction and parameters

I build six levels, G0 through G5. G0 is the original float64 RGB image in [0,1]. Repeated filtering uses step sigmas 1, 2, 4, 8, 16 pixels, reflected boundaries, and truncation at 3σ. The corresponding 1D kernel supports are 7, 13, 25, 49, 97 samples along each spatial axis. RGB channels are filtered independently. There is no resizing between levels.

Successive Gaussian variances approximately add, so the effective blur sigmas are 0, 1, 2.236, 4.583, 9.220, and 18.466 pixels. Each step sigma describes the additional filter, rather than the total blur. Increasing the step scale gives a wider range of spatial frequencies.

gaussian_stack = build_gaussian_stack(image, sigma_steps)
# Inside the loop: filter gaussian_stack[-1], keeping its dimensions.
laplacian_stack = build_laplacian_stack(gaussian_stack)
# L0 = G0 - G1, ..., L4 = G4 - G5, L5 = G5
reconstruction = laplacian_stack.sum(axis=0)

Subtracting neighboring Gaussian levels removes their shared smooth content. The remainder is an approximate frequency band. Adding all differences and the final residual telescopes back to G0.

Key ideas

  • A stack keeps the original sampling grid at every level; a pyramid reduces its dimensions.
  • There is no downsampling here, so corresponding pixels stay directly aligned across levels.
  • Gaussian levels retain increasingly smooth, low-frequency content.
  • Subtracting neighboring Gaussian levels cancels their shared smooth content, leaving an approximate frequency band.
  • The bands overlap; they are not disjoint hard frequency cutoffs.
  • The adjacent differences telescope: (G0−G1)+…+(G4−G5)+G5 = G0. Omitting G5 would lose the smooth content.
  • Signed Laplacian values need a centered display scale; clipping negatives would hide half of the response.

Implementation notes

In build_gaussian_stack, gaussian_filter(gaussian_stack[-1], ...) repeatedly filters the previous level. The RGB sigma tuple ends in zero to keep channels separate. build_laplacian_stack subtracts adjacent arrays and appends the final Gaussian residual. laplacian_stack.sum(axis=0) reconstructs the image. signed_display maps a signed band to 0.5 + band/(2×scale), using the maximum absolute value and a zero-band guard. Numerical arrays remain unchanged.

I used separate functions to build Gaussian stacks, build Laplacian stacks, and render figures. This keeps the CV operations easy to follow without needing a class.

Key ideas

  • Laplacian levels separate fine detail from broader variations; the final residual retains smooth color and shape.
  • A Gaussian mask stack uses progressively wider transitions for coarser frequency bands. Repeated filtering broadens the mask without changing its dimensions.
  • A hard cut switches every frequency at the same column, creating abrupt color and brightness changes.
  • Summing all blended bands, including the residual, reconstructs the composite.
  • Ordinary alpha blending applies one spatial weight to every frequency. Here each band uses its own mask scale.
  • The same mask weight broadcasts to R, G, and B; spatial filtering never averages different channels together.

Key Ideas: Custom Blends

  • The mask shape determines which source contributes at each location; one selects A and zero selects B.
  • Gaussian mask levels broaden the transition for coarse bands while retaining narrower transitions for fine detail.
  • An ellipse has a curved boundary defined by a quadratic equation, so it satisfies the nonlinear-mask requirement.
  • Eye alignment helps corresponding features meet, but different muzzle lengths, glasses, and face proportions still create artifacts.
  • Color and texture mismatch can remain because blending changes transitions rather than matching geometry or illumination.
  • Ordinary alpha compositing uses a single mask at all frequencies; multiresolution blending uses a different mask scale per band.

Most important thing I learned

The most important thing I learned is that the same Gaussian filtering idea connects all four applications. Smoothing made edges easier to isolate, subtracting the blur exposed detail for sharpening and hybrids, and repeating that decomposition let me blend different spatial scales. The experiments also showed the limits: sharpening did not recover lost detail, and a smoother blend did not fix mismatched faces. Choosing the scale, alignment, and boundary handling mattered as much as writing the filtering equation.
